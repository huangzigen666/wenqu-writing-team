# 公众号排版规范

唯一视觉参考：[标准文章](https://mp.weixin.qq.com/s/3ce9vSeMCz-IFTHoWTTUQg)。所有排版按参考样式还原，不自由发挥。

## 基础样式

| 元素 | 样式 |
|---|---|
| 正文 | `16px; line-height:1.82; color:#1f2937` |
| 加粗 | `color:#111827; font-weight:700` |
| 段间距 | `margin:0 0 14px` |
| 引用块 | `background:#f5f5f5; padding:16px 20px; border-radius:8px; color:#666` |
| 强调色 | `#dc2626` |

标题使用 5px 暗红左边框、浅灰背景和右侧圆角。Rex 判断使用 `#111827` 黑底白字卡片，标签色为 `#fca5a5`。Rex 提醒使用 `#fff1f2` 浅红底、`#fecdd3` 边框。

微信编辑器中的每个文本节点使用 `<span leaf="">` 包裹；颜色用 hex。禁止把 HTML 当纯文本转义。

## 内容硬规则

- 不出现具体竞品名，使用泛称。
- 案例分数和位次必须标注“数据脱敏，非原始数据”。
- 不得编造案例人物不知道排名等逻辑漏洞。
- Markdown 源文件不要重复写由脚本追加的“自主声明”和“文章来源”。
- 文章特有的 Rex 提醒写在 Markdown 中，由排版工具渲染。

## 插图与封面

- 每篇至少 3 张不同插图，与对应段落相关。
- 图片 URL 和说明动态读取，禁止在脚本中硬编码上篇文章的说明。
- 每篇生成新封面，不复用旧图。
- 多篇同日推送：头条使用 21:9；次条和三条的关键信息必须完整落在居中 1:1 安全区。

## 推荐流程

```bash
# 路线 A：推荐
/wechat-styler 文章.md --theme kami --components
push-wechat 文章.html "标题" --cover 封面图路径.png

# 路线 B：传统
python3 ~/.local/bin/wechat-format.py 文章.md
push-wechat 文章.html "标题" --cover 封面图路径.png
```

用户未明确要求推草稿箱时，只交付文件，不擅自发布。推送后用草稿列表接口确认草稿真实存在。

## 发布前验收

- [ ] 竞品名搜索结果为 0。
- [ ] 无 Markdown 标题符号残留。
- [ ] Rex 判断和 Rex 提醒卡片正确。
- [ ] 插图至少 3 张且图文匹配。
- [ ] “自主声明”和“文章来源”各出现 1 次。
- [ ] 案例数据已脱敏。
- [ ] 使用当前文章的新封面。
- [ ] 字体、行距、标题和卡片与参考文章一致。
