# 公众号文章排版与推送标准流程

> ⚠️ **一次说清楚，以后不返工。** 任何AI执行本流程时，严格按以下标准走，不需要问用户确认格式问题。

## 一、格式参考标准

**唯一参考文章：** https://mp.weixin.qq.com/s/3ce9vSeMCz-IFTHoWTTUQg

所有排版必须1:1还原此文章的视觉风格。不允许自由发挥。

**已验证通过的工具：**
- ✅ `wechat-format.py` — 正确还原参考样式（2026-07-25 验证通过）
- ❌ `wechat-styler --theme kami` — 生成的纸感杂志风不匹配，禁用

**排版规则已固化在 `wechat-format.py` 脚本中，不要改用其他排版工具。**

## 二、排版规则（硬性规定）

### 2.1 基础样式

| 元素 | 样式 | 说明 |
|:----|:----|:------|
| 正文字体 | 16px | 行高1.82，颜色#1f2937 |
| 加粗文字 | color:#111827;font-weight:700 | 关键句加粗 |
| 段间距 | margin:0 0 14px | 段与段之间 |
| 引用块 | background:#f5f5f5; padding:16px 20px; border-radius:8px; color:#666 | 灰色圆角卡片 |

### 2.2 标题样式

大标题（`#` / `##`）使用红边样式：
```html
<section style="margin:28px 0 13px;padding:10px 12px;
  border-left:5px solid #dc2626;background:#f9fafb;
  border-radius:0 8px 8px 0;">
  <span style="font-size:18px;line-height:1.45;
    color:#111827;font-weight:700;">
    <span leaf="">标题文字</span>
  </span>
</section>
```

### 2.3 Rex 判断（黑底白字卡片）

出现在文章开头或关键判断处：
```html
<section style="margin:0 0 18px;padding:15px 15px 13px;
  background:#111827;color:#fff;border-radius:8px;">
  <section style="font-size:13px;color:#fca5a5;
    font-weight:700;margin-bottom:6px;">
    <span leaf="">Rex 判断</span>
  </section>
  <section style="font-size:18px;line-height:1.58;font-weight:700;">
    <span leaf="">判断内容</span>
  </section>
</section>
```

### 2.4 Rex 提醒（浅红底边框卡片）

出现在文章尾部，风险提示用：
```html
<section style="margin:26px 0 4px;padding:15px;
  background:#fff1f2;border:1px solid #fecdd3;
  border-radius:8px;color:#374151;">
  <section style="font-weight:700;color:#dc2626;margin-bottom:6px;">
    <span leaf="">Rex 提醒</span>
  </section>
  <section><span leaf="">提示内容</span></section>
</section>
```

### 2.5 插图

- 每篇文章至少3张插图，必须各不相同，内容与文章对应段落相关
- **插图URL + 说明文字**必须从 `~/.hermes/wechat-images.json` 动态读取
  - 文件结构：`{"illust_urls": [...], "captions": ["图1说", "图2说", "图3说"]}`
  - 换文章时必须：①生成新配图 ②上传微信素材库 ③更新json的 illust_urls 和 captions
  - `wechat-format.py` 中**绝不允许硬编码**说明文字（2026-07-25 教训：旧图"三种AI产品的本质区别"串到高考文章）
- 封面图：使用 Pillow 或 guizang-social-card-skill 生成，每篇文章单独生成
- 封面图通过 `push-wechat --cover 本地路径` 推送

### 2.6 文章底部固定内容（由脚本自动追加，markdown中不要写）

以下内容由 `wechat-format.py` 自动追加到 HTML 尾部。**markdown 源文件中不要包含** `自主声明` 和 `文章来源`，否则会和脚本输出的重复（2026-07-25 教训：双Rex提醒+双自主声明+双文章来源）。

```html
<p>自主声明：该文章由 AI 辅助创作，最终判断和表达由黄昊 Rex 完成。</p>
<p>文章来源：黄昊Rex · 家庭决策系统创始人 · 高考升学规划师</p>
```

**Rex 提醒的**：
- 文章特有的 Rex 提醒内容（如"投档状态每天下午6点更新"）→ 写在 markdown 中用 `Rex 提醒` 加换行加内容，脚本渲染为浅红卡片
- 通用免责声明 → 已从脚本 footer 移除，不重复输出
- 脚本正则已兼容带冒号和不带冒号两种格式：`Rex 提醒：内容` 或 `Rex 提醒` 换行 `内容` 均可匹配

## 三、内容规则（硬性规定）

### 3.1 禁提竞品

❌ 不能出现任何具体竞品名称：优志愿、再致远、高考志愿君、夸克高考、元宝、DeepSeek、豆包等。
✅ 用泛称替代：「某某志愿卡」「某志愿填报系统」「某高考AI」「某AI聊天工具」

### 3.2 数据脱敏

❌ 不能说「排名未知」——家长当然知道孩子的排名。
✅ 写具体分数+位次，括号标注「（数据脱敏，非原始数据）」

### 3.3 案例引用

❌ 案例中不要出现逻辑漏洞（如妈妈不知道孩子排名）。
✅ 案例分数和排位必须标注数据脱敏。

## 四、封面图生成

每篇公众号文章推送前必须生成新封面图，不可重用旧图。
生成方式（按优先级）：

1. **推荐**：让 CodeBuddy 或 Codex 用 `guizang-social-card-skill` 的 Swiss/S01 模板 + Playwright 截图生成（图片质量最高，带设计感，正确的社交卡片风格）
2. **备选**：使用 Pillow 生成深色底+白色标题的简易封面（注意：必须用中文可渲染字体，`PingFang.ttc` 在本机不存在，需用 `STHeiti Light.ttc`）

保存到 `~/Desktop/公众号封面/`。

**封面颜色不定期更换**：不固定IKB蓝。4种accent轮换：`ikb` / `lemon-yellow` / `lemon-green` / `safety-orange`。下次推送选下一个。

### 4.1 多篇同天发布时的封面设计（2026-07-25 规则）

**当同一天推送多篇文章时（3篇连发），封面规则如下：**

| 文章位置 | 封面形状 | 设计要点 |
|:--------:|:--------:|----------|
| 第1篇（头条） | 长方形（21:9） | 正常设计，完整标题可见 |
| 第2篇（次条） | **正方形（1:1）** | 关键信息必须在正方形区域内可见，不要依赖长方形才显示的标题裁切 |
| 第3篇（三条） | **正方形（1:1）** | 同第2篇 |

**正文：** 公众号信息流中，头条显示长方形封面，次条和三条**只显示正方形裁剪区域**。因此第2、3篇文章在设计封面时，必须以正方形（1:1）为主——标题、关键词、核心信息全部放入正方形安全区内，不要有「长方形才显示」的关键信息。

生成方式：封面图本身还是生成长方形（2100×900），但设计时确保 1:1 正方形裁剪区（居中正方形）包含全部关键信息。

**推送方式：**
```bash
push-wechat 文章.html "标题" --cover ~/Desktop/桌面素材/公众号配图/封面-xxx.png
```

**`push-wechat --cover` 支持本地文件路径和远程URL**，内部自动上传到微信素材库获取 media_id。

## 五、发布流程

### 5.1 标准化发布步骤

**路线A — wechat-format.py（默认路线 — 排版规范已定稿，不可自由发挥）：**
```bash
# 1. 生成配图 + 封面（每篇文章单独生成，不可重用）
# 2. 上传配图到微信素材库
# 3. 更新 ~/.hermes/wechat-images.json（illust_urls + captions）
# 4. Markdown → HTML
python3 ~/.local/bin/wechat-format.py 文章.md
# 5. 推送到草稿箱（带新封面图）
push-wechat 文章.html "标题" --cover 封面图路径.png
```

**路线B — wechat-styler（⚠️ 仅限用户明确要求时才使用 — 其8个主题均为第三方设计风格，与Rex已定稿的排版规范不一致）：**
在 Codex 中调用：
```bash
/wechat-styler 文章.md --theme kami --components
```
可选主题：zhijian（暖纸感·默认）、kami（纸感编辑）、magazine-ink、magazine-indigo、magazine-forest、elegant、modern、minimal
**⚠️ 警告：** wechat-styler 的 `kami` 主题使用 #f5f4ed 米色底、楷体/宋体标题、#1B365D 深蓝强调色，与 Rex 定稿的 #f9fafb 灰底红边标题(#dc2626)样式完全不同。**未经用户明确授权，不允许用 wechat-styler 替代 wechat-format.py。** 用户已明确纠正一次，再犯即排版事故。`

### 5.2 工具

| 工具 | 路径 | 功能 |
|:----|:----|:------|
| `wechat-format.py` | `~/.local/bin/wechat-format.py` | Markdown→微信HTML（传统路线） |
| `wechat-styler` | Codex skill（~/.codex/skills/） | Markdown→公众号HTML（8主题+SVG动画+组件卡片） |
| `push-wechat` | `~/.local/bin/push-wechat` | 推送到公众号草稿箱（支持`--cover`单篇、`--multi`多篇文章合推为一篇多图文） |
| 配图缓存 | `~/.hermes/wechat-images.json` | illust_urls + captions |

## 六、验收清单（推送前逐项检查）

| # | 检查项 | 通过标准 |
|:--|:-------|:---------|
| 1 | 无竞品名 | 全文搜索：优志愿/再致远/夸克/元宝/DeepSeek/豆包 → 0结果 |
| 2 | 无###残留 | 搜索 `^###` → 0结果 |
| 3 | 有Rex判断 | 检查markdown源文件中有`Rex 判断`标签（不是HTML中，是md源文件） |
| 4 | 有Rex提醒 | 文章尾部有浅红卡片(`background:#fff1f2`) |
| 5 | 插图配文匹配 | 打开生成的.html检查图片说明文字是否与文章主题匹配（不是上篇文章的旧说明） |
| 6 | 无底部重复 | 全文搜索「自主声明」和「文章来源」各出现1次（不是2次） |
| 7 | 数据脱敏 | 案例分数旁标注「数据脱敏」 |
| 8 | 插图≥3张 | 各不相同，与内容对应 |
| 9 | 封面图是新图 | `push-wechat` 用了 `--cover` 传了当前文章的封面图，不是旧封面 |
| 10 | 排版1:1还原 | 对照参考文章检查字体/行距/红边/卡片样式 |

> **以上10项全部通过后，才能告知用户「已推送」，不允许边推边改。**

## 七、已知故障与修复（2026-07-25）

### 7.1 Rex 判断/提醒渲染失败
- **原因**：`wechat-format.py` 正则要求 `Rex 判断：内容` 带冒号格式，但 markdown 写的是 `Rex 判断` 换行 `内容`（无冒号），匹配不上
- **修复**：正则 `[：:]` → `[：:]?`（冒号可选）
- **触发**：markdown 中 `Rex 判断` / `Rex 提醒` 后跟换行再加内容即可触发，冒号可加可不加

### 7.2 插图永远是上篇文章的旧图
- **原因**：说明文字（如"三种AI产品的本质区别"）是硬编码在 `wechat-format.py` 中的
- **修复**：说明文字改为从 `~/.hermes/wechat-images.json` 的 `captions` 字段动态读取
- **换文章时必须**：①生成新配图 ②上传微信素材库 ③更新json（illust_urls + captions）

### 7.3 底部重复（双Rex提醒+双自主声明+双文章来源）
- **原因**：markdown 正文里写了 + 脚本 footer 又自动追加了一遍
- **修复**：脚本 footer 去掉 Rex提醒卡片，只保留 自主声明 + 文章来源；markdown 中不要写 自主声明 和 文章来源
- **预防**：验收清单第6项

### 7.5 Rex判断/Rex提醒缺失（2026-07-25 教训）
- **原因**：markdown 源文件中没有写 `Rex 判断` 和 `Rex 提醒` 标签，脚本的正则匹配不上，自然不渲染
- **修复**：在 markdown 正文中插入 `Rex 判断` 换行 `内容`（用于文章开头的黑底白字卡片）和 `Rex 提醒` 换行 `内容`（用于尾部的浅红底提示卡），冒号可加可不加
- **预防**：验收清单第3/4项新增检查markdown源文件中有无Rex标签

### 7.7 Pillow 生成中文图片乱码（2026-07-25 教训）
- **原因**：使用 `PingFang.ttc` 字体路径，但该文件在本机 macOS 上不存在。Pillow 静默改用默认字体，无法渲染中文字符，导致图片上中文变为乱码/方框。
- **修复**：改为使用 `/System/Library/Fonts/STHeiti Light.ttc`（确认存在的系统字体，支持中文渲染）
- **验证**：`python3 -c "from PIL import ImageFont; ft=ImageFont.truetype('/System/Library/Fonts/STHeiti Light.ttc',36)"` — 无异常即可用
- **预防**：Pillow 生成含中文的图片前，先用 os.path.exists() 确认字体文件存在
- **原因**：多篇文章共用一个 `~/.hermes/wechat-images.json`，`wechat-format.py` 从该 JSON 读取前3张图片 URL 插入每篇文章。多篇文章生成的 HTML 中，三篇文章的3张配图完全一样。
- **修复**：每篇文章的配图由 Codex 用 image-2 + guizang-social-card-skill 独立生成，独立上传微信图床获取 CDN URL。让 Codex 直接在生成的 HTML 中用 `data-src` 指向各文章专属的图片 URL，不使用 `wechat-images.json` 统一存取。
- **预防**：多篇同天发布时，在 `wechat-format.py` 生成 HTML 后，手动替换每篇文章的图片 URL 为各自独立的 CDN URL。
- **原因**：`push-wechat` 的 cover 地址是 ACCOUNTS 配置中的静态 URL，从不更新
- **修复**：`push-wechat` 新增 `--cover` 参数，支持本地文件路径。每次推送时单独传当前文章的封面图
- **预防**：验收清单第9项
