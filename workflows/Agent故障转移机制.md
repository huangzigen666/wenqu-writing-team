# Agent 故障转移机制

## 1. 定位与边界

问渠专家团是内容生产执行层；Decision OS 是判断资产层。二者不争夺同一层的权力：

- Decision OS 提供已经由用户确认的 Rule、Case 和适用边界。
- 问渠可把这些资产作为只读输入，转成选题、文章、核查、排版或数据产物。
- 问渠发现的新观点只能登记为候选，不得自动写回 Decision OS 的 `decision/`、`cases/` 或 `memory/`。
- 任一 Agent 的输出都是草稿或建议。最终判断、发布、部署、push、生产配置修改和用户数据删除均需用户明确授权。

## 2. 预授权范围

用户调用 `wenqu-dispatch <角色> --task <任务>`，视为只对“同一任务、同一职责、同一权限、同一验收条件”的有限替补授权。替补不得：

1. 扩大任务范围、修改输入事实或改变交付格式。
2. 从只读/草稿任务升级为写文件、发布、部署、push 或删除。
3. 绕过 Decision OS 的用户确认门或把建议冒充判断资产。
4. 因替补而降低事实来源、适用范围、证据或验收标准。

涉及外部写入或不可逆操作时，调度器只报告失败，不自动换人继续操作。

## 3. 什么算不可用

以下情况允许触发替补：额度耗尽、认证失效、网络不可达、CLI 缺失、服务崩溃、超时、非交互环境要求 TTY。仅有“进程存在”或退出码为 0 不算成功；标准输出为空、明显是登录/额度/连接错误，或未生成指定验收文件，均算失败。

内容质量不达标不是“不可用”。此时按审稿流程返修，不能靠换 Agent 逃避质量问题。

## 4. 有限重试与交接

- 每个执行者每棒只尝试一次；失败后进入下一个预设替补。
- 每棒最多尝试 3 个执行者。全部失败即停止并报告原始证据。
- 替补接收同一份交接包：角色、原任务、工作目录、权限模式、验收条件、已完成产物、失败类型和原始错误。
- 成功后立即停止，不自动进入下一道工序。
- 调度记录写到 `.wenqu-runs/`；该目录只存运行证据，不进入内容正文。

## 5. 能力替补矩阵

矩阵按能力而不是品牌排序。前者不可用才调用后者：

| 专家席位 | 主执行者 → 替补 1 → 替补 2 | 不变的职责 |
|---|---|---|
| 赵选题 | Codex → Claude Code → CodeBuddy | 选题研究与候选包 |
| 李文章 | Codex → Claude Code → CodeBuddy | 结构化写作 |
| 张素材 | agy → Claude Code → Codex | 对抗审查与证据攻击 |
| 周审稿 | Claude Code → Codex → CodeBuddy | 品控与 GEO 审查 |
| 刘风格 | Codex → Claude Code → CodeBuddy | 风格校准，不改事实 |
| 无查查 | Claude Code → Codex → CodeBuddy | 联网事实核验与来源记录 |
| 陈排版 | Codex → CodeBuddy → Claude Code | 平台适配与排版 |
| 王整理 | Codex → CodeBuddy → Claude Code | 素材归档与溯源 |
| 陈开发 | Trae → Qoder → Claude Code | 边界明确的本地开发工单 |
| 齐工程 | Qoder → Claude Code → Codex | 复杂工程；仍受安全门限制 |
| 码管线 | CodeBuddy → Qoder → Claude Code | 数据管线与结构化处理 |

赫值守不是生产执行者，不进入上述替补链。Hermes 不可用时可由本地调度记录保留证据；不能把“值守失效”解释成生产 Agent 获得额外权限。

## 6. 调用与验收

```bash
# 查看矩阵，不执行
wenqu-dispatch --matrix

# 默认只返回 stdout 草稿；主执行者不可用时有限替补
wenqu-dispatch 李文章 --task "按已确认选题写公众号母稿"

# 要求生成具体文件；文件不存在或为空即失败
wenqu-dispatch 无查查 --task "核验文章并写报告" --expect-file /绝对路径/核验报告.md

# 禁止替补，用于诊断单一执行者
wenqu-dispatch 张素材 --task "对抗审查这篇文章" --no-failover
```

报告必须列出实际执行者、尝试顺序、失败类型、验收结果和证据日志。署名只记录真正参与者。
